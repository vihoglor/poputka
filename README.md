# Отчет по Лабораторной работе № 1

**Проект:** Веб-приложение для поиска попутчиков.

## Что сделано

- **Шапка (Header):** Реализована шапка сайта с логотипом в формате SVG, блоком навигации `nav` и основными элементами меню: «Как это работает», «Водителям», «Войти», а также кнопкой «Предложить поездку». Логотип подключен в качестве изображения через тег `<img>`.

- **Главный экран (Hero):** Размещен основной заголовок `h2` с текстом «Дорога ближе, когда вы вместе» и поясняющий текст о назначении сервиса: поиске попутчиков и свободных мест в автомобилях.

- **Форма поиска поездок:** Реализована форма поиска, содержащая четыре поля:
  - город отправления;
  - город прибытия;
  - дата поездки;
  - количество пассажиров.
  

- **Преимущества сервиса:** Под формой поиска размещен дополнительный блок с тремя преимуществами: «Профили с отзывами», «Понятная цена» и «Удобный поиск».
<img width="1388" height="640" alt="image" src="https://github.com/user-attachments/assets/10d5669b-75bc-4ddb-a4ca-36bb4487f5a7" />

- **Блок популярных маршрутов:** Создан отдельный раздел «Популярные маршруты» с пояснением «Выберите маршрут — и найдите подходящую компанию». В разделе реализована сетка из **4 карточек поездок**.

- **Карточки поездок:** Каждая карточка содержит стоимость поездки за место, количество свободных мест, время отправления и прибытия, города маршрута, информацию о водителе, рейтинг, количество совершенных поездок и кнопку «Забронировать». Например, представлены маршруты Москва → Тула, Москва → Тверь, Казань → Уфа и Санкт-Петербург → Москва.

- **Информация о водителях:** В карточках поездок реализован отдельный блок с аватаром водителя, именем, рейтингом и количеством поездок. Для визуального оформления используются круглые элементы с инициалами водителей.

- **Интерактивные элементы:** Для кнопок, карточек маршрутов и ссылок реализованы плавные анимации. Карточки поездок при наведении поднимаются вверх и получают измененное оформление и тень. Основные кнопки также изменяют внешний вид при наведении.

- **Блок «Просто по пути»:** Добавлен информационный раздел, объясняющий процесс использования сервиса. Он состоит из трех последовательных шагов:
  1. **Найдите маршрут** — указать города и дату.
  2. **Выберите водителя** — сравнить время, цену, свободные места и отзывы.
  3. **Договоритесь о поездке** — связаться с водителем и уточнить детали отправления.

- **Визуальный стиль:** Сайт выполнен в современном стиле. Для элементов интерфейса используются полупрозрачные фоны, размытие, прозрачные границы и мягкие тени. Основным акцентным цветом является синий.

- **Фон:** На странице используются три декоративных размытых градиентных элемента в виде сфер. Они создают дополнительный визуальный фон и поддерживают общую стилистику интерфейса.

- **Адаптивность:** Для сайта предусмотрены несколько адаптивных режимов с использованием `@media`. На меньших экранах изменяются размеры контейнеров, карточек, формы поиска, логотипа, текста и элементов навигации. Сетка карточек также перестраивается с четырех колонок на две.

- **Подвал (Footer):** В нижней части страницы реализован футер с информацией об авторских правах и ссылками «Как это работает», «Водителям» и «Поддержка». Футер также оформлен в стиле стеклянного элемента.

# Отчет по Лабораторной работе № 2
## Проект: Веб-приложение для поиска попутчиков «Попутка» (SPA)

### Что сделано

* **Превращение статического макета в интерактивное SPA.** Проект из Лабораторной работы №1 был доработан: добавлена вся клиентская логика на чистом JavaScript (Vanilla JS). Приложение теперь состоит из главной страницы (`index.html`) и страницы поиска (`search.html`), которые используют общий файл `js/app.js`. Вся отрисовка интерфейса происходит на основе единого объекта состояния `state` по паттерну State-Driven UI (`UI = render(state)`).

* **Единое состояние приложения.** В `app.js` создан объект `state`, содержащий:
  * `items` — массив поездок;
  * `route` — параметры маршрута (откуда, куда, дата, количество пассажиров);
  * `searchQuery` — строка поиска;
  * `selectedCategory` — выбранный фильтр по количеству свободных мест;
  * `maxPrice` — ограничение по цене;
  * `minRating` — минимальный рейтинг водителя;
  * `sortBy` — режим сортировки.
  
  Любое изменение состояния вызывает функцию `render()`, которая перерисовывает соответствующие части DOM.

* **Динамический поиск.** На странице поиска реализовано текстовое поле (`#search-query`), которое фильтрует поездки в реальном времени по событию `input`. Поиск осуществляется по имени водителя, городам отправления и прибытия. Регистр символов не учитывается благодаря приведению к нижнему регистру (`normalize()`). Для вставки текста используется `textContent`, что исключает XSS-уязвимости.

* **Фильтрация.** Добавлены элементы управления:
  * Выпадающий список категорий (`#category-filter`) с пунктом «Все категории» и фильтрами по количеству свободных мест (1, 2, 3+);
  * Поле для максимальной цены (`#max-price`);
  * Выбор минимального рейтинга водителя (`#min-rating`).
  
  Все фильтры применяются совместно с поиском и параметрами маршрута. Предусмотрена кнопка сброса фильтров (`#reset-filters`), возвращающая значения по умолчанию.

* **Сортировка.** Реализован выпадающий список (`#sort-by`) с четырьмя режимами:
  * По дате и времени (сначала ближайшие / сначала поздние);
  * По цене (сначала дешевле / сначала дороже).
  
  Сортировка выполняется иммутабельно: исходный массив `state.items` не изменяется, создаётся его копия через `[...filtered].sort(...)`.

* **Модальное окно добавления поездки.** На главной странице добавлена кнопка «Предложить поездку», открывающая модальное окно (`#ride-modal`). Окно закрывается:
  * По кнопке-крестику (`[data-close-modal]`);
  * По клику на подложку (backdrop);
  * По нажатию клавиши `Escape`;
  * После успешной отправки формы.
  
  При открытии окна дата поездки ограничивается текущей датой (`min`), чтобы нельзя было выбрать прошедшую дату.

<img width="900" height="701" alt="image" src="https://github.com/user-attachments/assets/9862555f-9e2b-4045-b6e2-66d11fb5fced" />

* **Форма и клиентская валидация.** В модальном окне реализована форма (`#ride-form`) для добавления новой поездки. Валидация использует Constraint Validation API:
  * HTML5-атрибуты `required`, `minlength`, `maxlength`, `min`, `max`, `type="date"`, `type="time"` и др.;
  * Перехват отправки через `e.preventDefault()`;
  * Проверка `input.validity` для каждого поля;
  * Вывод понятных сообщений об ошибках под каждым полем (`[data-error-for]`) и общего сообщения над формой.
  

  При вводе корректных данных ошибки автоматически скрываются. После успешной валидации создаётся новая поездка, которая добавляется в `state.items`, сохраняется в `localStorage` и отображается в интерфейсе.

* **Сохранение данных в localStorage.** При любом изменении списка поездок (добавление, удаление) вызывается `saveRides()`, которая сериализует `state.items` через `JSON.stringify()` и сохраняет по ключу `poputka-v1`. При загрузке страницы `loadRides()` пытается прочитать данные из `localStorage`; если хранилище пустое или данные повреждены, загружаются демонстрационные начальные данные (`defaultRides`). Это обеспечивает постоянство данных между перезагрузками страницы.

* **Кастомные выпадающие списки городов.** На странице поиска поля «Откуда» и «Куда» оснащены подсказками (`#from-dropdown`, `#to-dropdown`), которые формируются из имеющихся в системе городов. Реализована фильтрация подсказок при вводе, выбор города кликом, закрытие списка при клике вне его. Всё работает на основе делегирования событий.

* **Обновление URL при поиске.** При отправке формы поиска на главной странице параметры маршрута передаются в URL страницы `search.html` (`from`, `to`, `date`, `seats`). На странице поиска эти параметры считываются через `URLSearchParams` и инициализируют состояние.

* **Чистота и безопасность кода.** Для вывода пользовательских данных используется исключительно `textContent` (создание элементов через `createElement` и установка текста), что предотвращает XSS. Запрещённые `var` и нестрогое сравнение `==` не используются; применяются только `const` и `let`, а также строгое `===`. Весь код организован в виде функций с чётким разделением ответственности: загрузка/сохранение данных, построение карточки, фильтрация, сортировка, рендеринг, инициализация страниц и модального окна. Сторонние библиотеки и фреймворки не используются.

* **Сохранение визуального стиля и адаптивности.** Проект унаследовал современный дизайн из Лабораторной работы №1: стеклянные элементы (Glassmorphism), синий акцентный цвет, декоративные градиентные сферы, плавные анимации. Сетка карточек и форма поиска адаптируются под мобильные устройства, горизонтальная прокрутка отсутствует.
